# Sabotage tables — checkout measure-prep (unit 7), 2026-09-24

One deliberate defect per row; the owning guard must fail; restore from a
backup COPY, never `git checkout`. Plane rows ran on a held fixture plane,
one suite file per row, the vanilla dist rebuilt where the defect was a
build input. Verdicts come from the runner's exit codes
(`scratchpad/sabotage.mjs`, in the session's scratchpad), never by eye.

## Two defects in the runner itself, both exposed by a CONTROL row

1. The first pass reported EVERY row "CAUGHT" with exit code 126 — the
   control included. 126 is "cannot execute": the login shell (`bash -lc`)
   handed `node` to a version-manager shim with no version set, and no
   guard had run. A table that reads "caught" on a guard that never ran is
   the vacuous pass in its purest form. Fixed (`bash -c`, which inherits the
   session's toolchain); the table below is the second pass.
2. Round 2's control BROKE on the fixed tree: the runner kept a file's
   backup from the FIRST run that ever touched it, so round 2's restores
   rewound `collect.ts`, `cart-summary.css` and `render.mjs` to their
   round-1 state — undoing the type-card redesign, the derived track and a
   comment fix. The two control failures (a `pointerdown` first input; a
   `NaN` track) were exactly those rewinds. Fixed (backups fresh per run),
   the tree repaired, round 2 re-run in full; the table below is that run.
