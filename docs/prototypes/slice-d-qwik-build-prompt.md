### Qwik-specific things to measure EARLY, before building much

Each of the last three slices had one surprise that would have been cheap to find early and expensive to find late. The likely candidates here:

1. **`q:container` and friends may sit on `<html>` or on a wrapper element.** This is the big one. If Qwik puts attributes on `<html>`/`<body>`, those are *contract surface* (the normalizer serializes the document element's own attributes deliberately — a dropped `lang` is real a11y drift) and need declared registration. If instead Qwik wraps content in an **extra element**, you have slice C's `<astro-island>` problem: `dropElementSelectors`' content-aware guard (`el.childElementCount === 0`) refuses to remove an element that has element children, so no registration can excuse it and the DOM check will fail. **Build a throwaway scaffold and look at the real emitted HTML before committing to a page structure.** Slice C settled its island-vs-script decision exactly this way, and the measurement inverted the intuition.
2. **Does Qwik's escaping match the reference renderer's `esc()`?** Astro's did (byte-identical via `html-escaper`, decimal `&#39;`); React's did NOT (`&#x27;`), which forced a second escaper in the origin suite's raw-string assertions. Check `packages/reference/render/lib.mjs`'s `esc()` against whatever Qwik emits, empirically.
3. **Whitespace.** Astro's `compressHTML` strips inter-element whitespace the master has (fine here — every inline-child container on the editorial page is flex or grid, so whitespace-only children never become items). Check what Qwik does. The zero-tolerance pixel leg is what proves it either way.
4. **Resumability is not hydration — so slice B's failure mode may not apply, but verify rather than assume.** Slice B's bug was React's hydration mismatch *deleting* the front Worker's injected chrome from `div#pm-chrome-slot`, invisible on a fast machine. Qwik resumes rather than reconciles, so it likely never re-renders that subtree — but it does attach global listeners, so confirm the chrome survives and the cart button works. `Emulation.setCPUThrottlingRate: 4` via Playwright is the technique that reproduced the slice-B race on demand.
5. **Qwik's `<script type="qwik/json">` state payload is a script element** and therefore already a declared ADR-0008 delivery freedom — free, no registration needed. Confirm it is a script element and not something contract-visible.

### Immediately after slice D — do NOT skip this

**Issue [#16](https://github.com/Robert-Lark/project-matrix/issues/16), the `bench-accounting-fix` ticket, runs in the session right after slice D and before slices E/F.** This is Rob's explicit scheduling call (2026-07-24): document the measurement defects well and address them at the right time, not at the end of the project. `docs/decision-map.md` carries the ticket and the timing rationale. In short:

- **Inline `<script>`/`<style>` bytes are invisible to the KB accounting.** `tools/bench-runner/src/collect.ts` derives `buckets.js`/`initialJsBytes` from resource-timing entries keyed by URL extension, so astro's *inlined* 1,247 B cart bundle reports **0 KB initial JS** while vanilla — the NO-RUNTIME control — reports ~1 KB for the identical enhancement. That inverts the render axis's headline row on the one surface whose thesis is how much JavaScript prose needs. Rigging the variant (`assetsInlineLimit: 0`) was rejected as inventing a request the paradigm would not make; the fix belongs in the harness and needs an ADR-0001 §3 addendum for the double-counting question (those bytes already live in `buckets.html`).
- `tools/bench-runner/src/cpu.ts`'s `LOCAL_PLANE_INSPECTORS` omits every real variant's inspector (`pm-vanilla` 9235, `pm-react-next` 9236, `pm-astro` 9237, and now qwik's), so a local bench attributes zero CPU to the Worker that served the page. Not a one-line fix: `CdpConnection.open` throws on an absent inspector, so the port list and its failure tolerance must be decided together. `pm-blog` stays OUT (ADR-0009 puts it outside every measurement fence).
- ADR-0003 §2's "CSS its native way" is currently nominal — all editorial variants ship the shared stylesheets as raw verbatim copies, so their CSS cells are identical by construction. §8 forces that only for the font files and `fonts.css`.
- **Related design question worth folding into the same pass:** `PublishedReading` (`packages/switcher/src/lab.ts`) carries a single `value` with no interval, while `bandsOverlap` exists only at bundle level governing the one Fit sentence. So the reading table cannot honestly show *per-metric* "who wins" — which is what a visitor actually wants. If the HUD is to rank per row, the bundle contract needs a band per reading. Both are "make the reading table able to tell the truth" work; doing them together means one pass over that contract instead of two.

## Standing discipline (carried forward from slices A–C; apply all of it)

- **Verify library behavior against installed source and official docs, never training recall.** Next 16 shipped an `AGENTS.md` warning that its APIs differ from training data, and it was right twice. Astro shipped an `AGENTS.md` (symlinked as `CLAUDE.md`, so it auto-loads) that told agents to run `astro dev` — which serves no injected chrome, no `/_pm/*` measurement client, and 404s every image, while looking fine. **Audit any scaffolded agent file; do not keep it as "starter fidelity" if it misdirects.** Check whether Qwik's starter ships one.
- **Run the saved `verify-slice` workflow in the background while probing inline in the foreground.** Args are JSON, not a string: `Workflow({name:"verify-slice", args:{issue, scratchDir, context, repoDir}})` where `issue` is a non-numeric decision-map ticket name (there is no GitHub issue for the slices), `repoDir` is your worktree, and `scratchDir` is the session scratchpad. Four sequential lenses, ~2h wall clock, findings streamed to disk. On slice C it returned 13 findings; 10 were adopted and **two of those were holes in that session's own earlier fixes**. Adopt or refute every finding against source — never on authority alone — and prove new assertions non-vacuous by sabotage.
- **Prove locally in BOTH snapshot modes before committing:** default (fixture) and `PM_SEED_DIR=tools/snapshot-capture/crate`. Expect the full origin suite green in each.
- **If a test fails only in CI and passes locally, do not assume flakiness and do not loosen the assertion.** Root-cause it. Known classes, all real, all previously mistaken for flakes:
  - *Fresh-clone* failures — a typecheck that imports generated build output fails where no build has run. Fixed for astro with a turbo `dependsOn: ["topo","build"]` **and** declaring the generated file a build `output` (a cache hit otherwise replays `dist/` without it). Test by deleting the file and re-running.
  - *Generated framework output picked up by root `eslint .`* — `**/.next/**`, `**/.open-next/**`, `**/.astro/**` are already ignored; Qwik will likely add one.
  - *Cold-cache compression* — a brand-new URL's first hit on the deployed plane is a cache MISS and Cloudflare serves that MISS **uncompressed**, so the transport-parity assertion measures cache state. Hardened in `wireEncoding` (warms until an encoding appears, bounded, deployed-only), so slice D should not hit it — but if you see an empty `content-encoding`, that is the mechanism.
  - *Hydration/timing races* invisible on a fast machine — reproduce with Playwright + `Emulation.setCPUThrottlingRate: 4`.
- **After any push to main, explicitly check the DEPLOY job's own conclusion.** Green `check` and `origin` are NOT sufficient — deploy is a separate job and has failed twice while the live origin was healthy. When in doubt `curl` the deployed origin directly (send a browser UA: workers.dev edge 1010-blocks `python-urllib`). For the origin suite against the deployed plane, the corp proxy needs `NODE_EXTRA_CA_CERTS` — export the "Gateway CA - Cloudflare Managed" root from the System keychain.
- **One commit, explicit paths, never `git add -A`** (Rob drafts files in-tree in parallel). Update `docs/build-log.md` (Phase 8, new `editorial-build slice D` subsection), `docs/decision-map.md`'s editorial-build Status line, `docs/prototypes/finish-line-handoff-prompt.md` (in the MAIN checkout, untracked), and memory.
